# 開發與測試計畫

## 目標
將專案從基礎單機營運工具逐步發展為符合公司內部營運的本機優先系統，而不在未完成驗證前開放手機遠端存取。

## 開發順序
### 第 1 階段：修復與穩定
- 修正 SQLite 初始化與資料庫安全
- 建立備份、還原與移機備份流程
- 建立測試與驗證範圍
- 確認本機資料存放位置與資料分離

測試重點：
- `setup_database()` 可建立必要資料表
- `backup_database()` 能產生備份檔
- `restore_database()` 可正確還原資料
- 不能以假資料替代真實資料來源

### 第 2 階段：交易模型
- 進出貨、庫存、平均成本、毛利
- 應收應付與現金流
- 報表輸出與匯出

測試重點：
- 交易輸入驗證
- 庫存計算與負庫存警示
- 費用與毛利正確性

### 第 3 階段：行情來源整合
- 豐興每週開盤、歷史價格與週變化
- COMEX / LME / SHFE / 日本與美國廢鋼
- 匯率換算與來源標示
- 圖表分析與領先/落後情況

測試重點：
- 來源標示完整
- 輸入依據驗證
- 不接受未授權的假行情

### 第 4 階段：客戶與易用性
- 客戶地圖與聯絡資訊
- 回訪提醒與開發提醒
- 長輩式 UI

測試重點：
- 表格 readability
- 大按鈕與長輩操作流程
- 例外錯誤提示

### 第 5 階段：權限與手機安全存取
- 使用者帳號與權限
- 專用安全驗證與手機入口
- 部署與升級流程

測試重點：
- 只有本機 localhost 可用
- 權限邊界
- 外部存取未啟用

## 測試規範
- 所有重要功能都要有測試並在提交前執行
- 若功能未經測試，不能宣稱已完成
- 不在測試中使用假即時行情，除非明確標註為範例或停用
- 測試資料只使用本機測試數據，不提交真實客戶資料

## 版本控管與提交
- 每個階段完成後需確認差異與測試結果
- 提交前僅保留專案相關檔案，不納入公司敏感資料
- 若需要外部憑證或業務規則，需在文件中標示待確認
